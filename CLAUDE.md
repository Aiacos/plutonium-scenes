# Constitution

These principles are **mandatory** for all work in this repository.

1. **Quality first** — Prioritize code simplicity, quality, correctness, security, readability, and maintainability.
2. **Design before code** — Plan the architecture before implementation, apply appropriate design patterns, and use object-oriented programming where it provides clear benefits without unnecessary complexity.
3. **Verify dependencies** — Research and verify SDKs, libraries, and APIs against official documentation before integrating them, and document relevant versions, constraints, and usage decisions.
4. **Meaningful tests** — Define and maintain meaningful testing standards, ensuring that automated tests and checks validate actual behavior, cover critical workflows and failure cases, and detect regressions rather than merely passing.
5. **Automated debugging & validation** — Implement automated debugging and validation workflows to identify issues, investigate root causes, verify fixes, and prevent recurring failures.
6. **Pre-commit checks** — Automatically run formatting, linting, applicable type checks, compilation or build steps, and relevant tests before every commit, and resolve failures rather than bypassing checks.
7. **Reliable CI/CD** — Maintain consistent, useful, and reliable CI/CD pipelines that enforce quality standards, execute effective checks and tests, and prevent invalid changes from being merged or deployed.
8. **Measured performance** — Define performance requirements, measure relevant workloads, and optimize verified bottlenecks without compromising correctness or maintainability.
9. **Consistent UX** — Maintain a consistent user experience across interfaces, interactions, terminology, feedback, and error handling.
10. **Scoped subagents** — Use subagents appropriately for clearly scoped tasks, with explicit responsibilities, sufficient context, and verification of their outputs.
11. **Plugins & skills** — Use Superpowers and Impeccable plugins and skills wherever available and appropriate to the task.
12. **Living documentation** — Write and continuously update technical and user documentation so that it accurately reflects the implementation, configuration, workflows, and known limitations.
13. **Project ledgers** — Maintain `TODO.md`, `SECURITY.md`, and `CHANGELOG.md` as clear, concise, and easy-to-update documents, using checklists and references where appropriate while preserving each file's intended purpose.
14. **Consistent icons** — Use consistent icons for corresponding sections across the README and other documentation.
15. **Regular cleanup** — Regularly clean up the repository, identify and remove dead code, unused dependencies, obsolete files, and redundant implementations, and verify that cleanup preserves expected behavior.
